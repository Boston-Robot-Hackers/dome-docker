- [x] Added `claude-code` and `kimi-code` to `manifest/tools.txt` (curl-installed CLIs, same pattern as `mcfly`). Both installers pipe to `bash` (per each tool's documented install command), but `tools.txt`'s only method, `curl-sh`, pipes to `sh` — extended `bare-metal-base.sh`'s tool installer with a new `curl-bash` method rather than mismatching interpreters. Regression tests: `tests/test_f01_manifest.sh` asserts both `tools.txt` sections exist and that `bare-metal-base.sh` handles `curl-bash`. While adding the assertions, found `assert_field()` itself was broken for any bracketed key (`[mcfly]`, `[claude-code]`) — `grep -q "^${key}"` treats an unquoted `[...]` as a regex character class, not a literal match; `[mcfly]` "passed" only by accident (`m` fell inside the resulting class), and `[claude-code]` hit an invalid descending range (`e-c`) and errored outright. Fixed `assert_field` to use `grep -qF` (fixed-string match) — the semantics every caller actually intended.
- [x] `manifest/repos.txt`'s `[ros_ws]` section entries had 2-space leading indentation (from the same uncommitted edit that added `dome_mission`/`dome_nav`/etc.), but `bare-metal-build.sh`'s `clone_section` extracts entries via `awk ... f && /^[^#[:space:]]/`, which requires the first character to be non-whitespace. Every indented line failed that match, so the *entire* `[ros_ws]` section silently produced zero repos on `git pull` + rerun on the Pi — not just the new entries. Existing packages on disk (from before the indentation was introduced) masked the bug; only the newly-added repos (`dome_nav` etc.) exposed it, since they had never been cloned. Fixed by removing the indentation, restoring the flat style used by every other section (`[root]`, `[root-pi]`, `[uros_ws]`). Regression test: `tests/test_f01_manifest.sh` "repos.txt entries parse via clone_section's awk extraction" — runs the exact extraction awk per section and asserts entry count > 0 (would have caught this immediately; missed at `/checkpoint` time because existing style/format checks didn't exercise the clone-time extraction path).
- [x] `bare-metal-build.sh`'s `clone_section` had no skip-existing check — `git clone` into an already-cloned, non-empty dest dir fails, and `set -e` + the explicit `|| exit 1` trap meant the whole script died at the *first* already-cloned repo on any rerun, never reaching new repos added later in `manifest/repos.txt`. Hit live: after adding `dome_nav`/etc. to the manifest, rerunning the script to pick them up would've failed immediately at `better_launch` (first entry, already cloned) instead of reaching the new repos further down the list. Fixed: `clone_section` now checks `[[ -d "${base_dir}/${dest}" ]]` and skips with a log line instead of attempting the clone. Regression test: `tests/test_f01_manifest.sh` "clone_section skips already-cloned repos" (static grep — real clone behavior needs network/root, consistent with other bare-metal script checks in this suite).
